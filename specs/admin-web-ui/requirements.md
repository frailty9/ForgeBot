# Admin Web UI 需求

## 1. 背景与目标

ForgeBot 的核心消息、LLM、结构化检索、知识沉淀、OneBot 与 MCP 链路已经完成基础验证。下一阶段提供随 ForgeBot 部署的 Web 管理控制台，使管理员无需登录部署机器终端，即可查看运行状态、调整应用层配置、维护密钥，并执行受控运维操作。

首期控制台面向单实例、自托管部署。它只调用受保护的管理 API，不直接读写 JSON、YAML、SecretStore 或 runtime 内部对象。

## 2. 用户故事

- 作为实例管理员，我希望输入管理令牌后进入控制台，并在刷新页面后安全地恢复本地会话。
- 作为实例管理员，我希望在首页看到 runtime、LLM、平台连接器、检索、反思和消息 Gate 的关键状态。
- 作为实例管理员，我希望通过结构化表单修改 LLM、Bot、Gate、检索、平台、管理员、运维群组、反思、MCP 和 Skill 配置。
- 作为实例管理员，我希望在应用配置前先校验，并清楚看到本次操作将热更新、重建组件还是软重启 runtime。
- 作为实例管理员，我希望配置版本冲突时不会静默覆盖其他修改，并可以重新加载后再处理差异。
- 作为实例管理员，我希望查看配置历史并回滚到指定版本。
- 作为实例管理员，我希望只能写入、替换或删除 LLM API Key，控制台永远不能读取其正文。
- 作为实例管理员，我希望手动重载文档索引、触发反思扫描或软重启 runtime，并看到明确结果。

## 3. 首期信息架构

首期控制台包含四个一级页面：

1. **概览**：实例健康、runtime 状态、当前配置版本、Gate 统计、LLM 密钥状态及关键组件摘要。
2. **配置**：按领域编辑运行时配置，支持校验、保存、错误定位和版本冲突处理。
3. **运行维护**：软重启、结构化索引重载、反思扫描，以及最近一次操作结果。
4. **版本历史**：配置版本摘要、来源、更新时间和回滚操作。

API Key 维护作为 LLM 配置中的独立操作区，不与普通配置表单一同提交。

## 4. 功能范围

### 4.1 认证与会话

- 使用现有 Bearer 管理令牌认证，不在首期引入用户、角色或数据库会话。
- 管理令牌只保存在当前浏览器会话存储中，不写入 URL、日志或构建产物。
- 收到 `401` 时清除当前认证状态并返回登录界面。
- UI 和 API 默认同源部署；跨域独立部署不属于首期默认方案。

### 4.2 概览

- 展示健康、就绪和 runtime 当前状态。
- 展示当前运行时配置版本、更新时间和配置来源。
- 展示 LLM 协议、Base URL、模型和 API Key 是否已配置，不展示密钥正文。
- 展示启用的平台连接器、群组绑定、MCP 服务和结构化检索状态。
- 展示 Gate 当前统计和 runtime 最近错误（如果后端状态提供）。

### 4.3 配置编辑

- 使用按领域分组的结构化表单，不以裸 JSON 编辑器作为主要入口。
- 覆盖 `bot`、`gate`、`llm`、`search`、`platforms`、`administration`、`reflection`、`operations` 和 `extensions`。
- 支持动态增删连接器、群组绑定、管理员、运维群组和 MCP 服务。
- 对协议、transport、布尔值、时长、数值范围和引用关系提供匹配的控件与前端提示。
- 保存前调用服务端校验；服务端仍是最终校验权威。
- 保存时携带 `expected_version`，禁止默认强制覆盖。
- 保存成功后以服务端返回快照刷新界面；失败时保留未提交草稿。
- 静态 YAML 配置仅只读展示，不提供伪热更新能力。

### 4.4 LLM API Key

- 只展示 `configured`、更新时间和非敏感状态。
- 提供独立的写入/替换操作，输入框不得预填现有值。
- 提供带二次确认的删除操作。
- API Key 不进入普通配置草稿、浏览器持久化状态或配置差异视图。

### 4.5 运维操作

- 支持软重启 runtime，并要求填写或生成操作原因。
- 支持重新构建结构化检索索引。
- 支持手动触发反思扫描。
- 危险或有中断感知的操作需要明确确认，提交期间禁止重复触发。
- 操作完成后展示成功结果或服务端错误，不以静默 toast 代替关键状态反馈。

### 4.6 配置历史与回滚

- 展示版本、时间、来源等服务端已有摘要。
- 回滚前展示目标版本并要求确认。
- 回滚请求携带当前 `expected_version`，冲突时不得自动强制回滚。
- 回滚成功后刷新当前配置与 runtime 状态。

## 5. 验收标准（EARS）

1. 当未认证用户访问控制台时，控制台应显示令牌登录界面，且不得提前请求或展示管理数据。
2. 当管理员提交有效令牌时，控制台应通过管理 API 验证令牌并进入概览；令牌不得出现在 URL 或日志中。
3. 当任意管理请求返回 `401` 时，控制台应清除会话令牌并要求重新认证。
4. 当管理员打开概览时，控制台应展示 runtime 状态、当前配置版本、LLM 非敏感状态和可用组件摘要。
5. 当管理员打开配置页时，控制台应将运行时配置按领域映射为结构化表单，并保持未知敏感值不可见。
6. 当管理员请求校验草稿时，控制台应调用服务端校验接口；校验失败时不得提交配置，并应将错误展示在可定位的位置。
7. 当管理员保存有效草稿时，控制台应携带当前 `expected_version` 提交完整 runtime 配置，并用服务端返回快照更新本地状态。
8. 当服务端返回版本冲突时，控制台应保留本地草稿、提示配置已被其他操作更新，并提供重新加载入口；不得自动强制覆盖。
9. 当管理员写入 LLM API Key 时，控制台应通过独立密钥接口提交，完成后清空输入值，并且后续任何响应或页面状态都不得包含密钥正文。
10. 当管理员删除 LLM API Key 时，控制台应先二次确认，成功后只显示未配置状态。
11. 当管理员执行软重启、索引重载或反思扫描时，控制台应防止重复提交，并展示该次操作的明确结果。
12. 当管理员查看配置历史时，控制台应展示服务端返回的版本摘要；当管理员确认回滚时，应使用当前版本进行乐观并发保护。
13. 当管理 API 暂时不可用时，控制台应保留未提交草稿，并提供可理解的错误状态和重试入口。
14. 当控制台在窄屏设备打开时，核心查看与紧急运维操作应保持可用；复杂配置编辑允许提示使用更宽屏幕。
15. 当 ForgeBot 构建发行包时，控制台静态资源应能随单个服务部署并由同一监听地址访问，不要求额外运行 Node.js 服务。

## 6. 非目标

- 首期不实现多用户、RBAC、OAuth、审计数据库或远程账户体系。
- 首期不提供任意 YAML、环境变量或部署机器文件的在线写入。
- 首期不提供日志实时流、聊天记录浏览或消息内容持久化。
- 首期不提供可视化 Skill/MCP 制作器，只管理现有配置契约。
- 首期不新增业务定制工具或平台介绍能力。
- 首期不以移动端完成全部复杂配置编辑为目标。

## 7. 约束与后续设计问题

- 前端只能依赖公开 HTTP 管理契约；后端内部 Go 类型不得成为隐式耦合接口。
- 所有高风险操作必须沿用后端鉴权、校验、版本控制和回滚能力。
- 第一版优先单体同源部署，前端产物应可嵌入 Go 二进制或随服务静态托管。
- 样式层引入 Sass/SCSS 是为了通过嵌套、变量、模块拆分等语法改善 CSS 的整洁性、可读性和长期维护性；避免使用可能展开为重复 CSS 的 mixin 等抽象，持续控制静态资源体积。
- 视觉设计、前端框架、静态资源路由和 API 错误模型将在设计阶段确定。
- 若现有 API 缺少概览所需的聚合状态或稳定错误码，应在设计阶段以最小后端扩展补齐，不允许前端解析错误字符串维持核心流程。

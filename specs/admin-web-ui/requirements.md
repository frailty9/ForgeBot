# Admin Web UI 需求

## 1. 背景与目标

ForgeBot 已具备运行时配置、LLM、平台连接器、群组绑定、结构化检索、MCP/Skill 和运行维护能力。Admin Web UI 为单实例自托管部署提供浏览器控制台，使管理员不登录部署机器终端也能观察状态、修改应用层配置并执行受控运维操作。

控制台只依赖 ForgeBot 的 HTTP 管理 API，不直接读取 YAML、JSON、SecretStore 或 Go 内部对象。前端最终随 ForgeBot 单体发布。

## 2. 用户故事

- 作为管理员，我希望通过管理令牌进入控制台，并在关闭标签页后自动结束会话。
- 作为管理员，我希望概览页先展示连接器、已连接群组、LLM 配置和工具/MCP，而不是无关指标。
- 作为管理员，我希望点击概览中的配置卡片后直接进入对应的配置关注点。
- 作为管理员，我希望在配置页按关注点编辑 Bot、LLM、Gate、检索、平台、反思、运维和扩展配置。
- 作为管理员，我希望配置修改先进入草稿，经过服务端校验后再应用，并能看到版本冲突。
- 作为管理员，我希望 API Key 只可写入或删除，任何页面都不能读取密钥正文。
- 作为管理员，我希望在配置页重新读取服务端快照，在运行维护页执行索引重载、反思扫描和软重启。
- 作为管理员，我希望查看配置历史并在乐观并发保护下创建回滚版本。
- 作为管理员，我希望页面在浅色、深色和跟随系统之间切换，且不影响业务状态。

## 3. 页面与导航

首期包含四个一级页面：

1. **概览**：连接器、群组、LLM、工具/MCP、结构化检索和最近操作摘要。
2. **配置**：按关注点拆分的应用层配置编辑器。
3. **运行维护**：状态刷新、索引重载、反思扫描和 runtime 软重启。
4. **版本历史**：配置版本、来源、时间和回滚。

配置一级菜单允许展开二级菜单：

- Bot 与提示词；
- LLM 与密钥；
- 消息 Gate；
- 结构化检索；
- 平台连接与群组；
- 反思与文档沉淀；
- MCP 与 Skill；
- 管理员与运维群组。

概览卡片到配置页面的跳转使用稳定的 section 标识，例如：

```text
/admin/config?section=llm
/admin/config?section=platforms
/admin/config?section=extensions
```

卡片跳转必须保留当前认证会话，并在配置页定位到对应 section。未实现后端数据的预留卡片可以展示为不可编辑状态，但不能伪造统计结果。

## 4. 功能范围

### 4.1 认证

- 使用已有 Bearer 管理令牌。
- 令牌仅保存在当前标签页的 `sessionStorage`。
- 通过 `GET /v1/admin/config` 验证令牌并获得首个快照。
- 任意管理请求返回 `401` 时清除会话并回到登录页。
- 令牌不得出现在 URL、页面可见文本、日志或普通错误对象中。

### 4.2 概览

- 顶部全局状态显示 runtime 状态词和状态点。
- 概览标题只保留页面标识和主标题，不展示重复的站点标识或长说明。
- 连接器卡片可跳转到平台连接配置。
- 群组卡片可跳转到平台群组配置。
- LLM 配置卡片可跳转到 LLM 与密钥配置。
- 工具/MCP 卡片可跳转到 MCP 与 Skill 配置。
- 结构化检索摘要可跳转到检索配置或运行维护页。
- LLM 花费统计作为后端能力就绪前的预留区，不显示虚构数据。
- 最近操作展示真实可获得的运行维护结果；后端没有活动历史时显示空状态。

### 4.3 配置编辑

- 服务端快照与本地草稿分离。
- “刷新配置”是配置页局部操作；存在未保存草稿时必须先提示。
- “校验”只调用服务端校验，不改变 runtime。
- “应用”必须携带 `expected_version`，成功后以服务端返回快照替换草稿。
- 版本冲突时保留本地草稿，不自动强制覆盖。
- 数组配置使用可增删的结构化行编辑器；不把全部配置作为主要 JSON 文本框。
- 高级字段可提供折叠 JSON 预览，但不能绕过结构化字段校验。
- 每个配置 section 显示影响级别：`LIVE`、`REBUILD`、`RESTART` 或 `STATIC`。

### 4.4 密钥

- LLM API Key 使用独立写入接口。
- 输入框不预填旧密钥，提交成功后立即清空。
- 页面只展示是否已配置、版本和更新时间等非敏感状态。
- 删除密钥必须二次确认。

### 4.5 运行维护与历史

- 运行维护页调用现有 runtime restart、search reload 和 reflection scan 接口。
- 请求期间禁用同一操作，并显示真实等待状态。
- 软重启要求填写原因并明确可能的短暂中断。
- 历史页显示版本摘要，回滚创建新版本，不删除历史。
- 回滚携带当前版本作为 `expected_version`，冲突时停止操作。

## 5. 验收标准

1. 当未认证用户访问 `/admin/` 时，系统应显示登录界面且不请求管理数据。
2. 当管理员提交有效令牌时，系统应加载概览快照并将令牌保存到当前标签页会话。
3. 当管理 API 返回 `401` 时，系统应清除令牌并回到登录界面。
4. 当管理员点击连接器、群组、LLM 或 MCP 卡片时，系统应进入对应配置 section，并在地址中保留稳定 section 标识。
5. 当管理员修改配置字段时，系统应只修改本地草稿，不立即改变 runtime。
6. 当管理员刷新配置且草稿未保存时，系统应先提示并在确认后重新读取服务端快照。
7. 当服务端校验失败时，系统应显示字段或 section 级错误且不得提交应用。
8. 当保存时版本不一致时，系统应保留本地草稿并提示重新加载或手动合并。
9. 当管理员写入或删除 API Key 时，任何响应、状态或错误信息都不得包含密钥正文。
10. 当管理员执行索引重载、反思扫描或软重启时，系统应禁止重复提交并展示真实结果。
11. 当管理员切换主题时，系统应只改变视觉令牌，不重建业务状态或请求管理 API。
12. 当系统未提供花费统计数据时，概览应展示明确的预留状态，不得使用示例数字冒充真实统计。
13. 当窗口宽度大于等于 1100px 时，导航应展开并显示一级、二级文字；低于该宽度时应收缩为图标轨。
14. 当页面内容超过视口高度时，左侧导航和右侧主内容应独立滚动，顶部条保持固定。
15. 当构建发行包时，Admin Web UI 应能作为静态资源嵌入 Go 服务，不要求生产环境运行 Node.js。

## 6. 非目标

- 首期不实现多用户、RBAC、OAuth 或数据库审计系统。
- 首期不在线写入静态 YAML、环境变量或部署机器文件。
- 首期不保存或浏览历史聊天记录。
- 首期不实现 LLM 花费统计后端，只预留前端信息位。
- 首期不提供可视化 MCP/Skill 编排器。

# 群知识反思与升格需求草案

## 1. 目标

ForgeBot 不保存聊天历史，但应能在受控群组中观察短期消息，并定时发现可复用的管理员回答，将其整理为 Bot 托管的 Markdown 知识。首版只把明确的“管理员引用普通成员问题作答”视为强关联候选，避免仅凭消息邻近关系误配问答。

## 2. 范围

- 消息只进入有界内存缓冲，受群组白名单、TTL、单群条数和总字符数限制；
- 定时扫描缓冲中尚未处理的消息，不调用平台历史消息接口；
- 只处理已由运行时身份解析器标记的管理员消息；
- 问题与答案优先由 `ReplyToMessageID` 确定，不把普通相邻消息自动配对；
- 反思器判断内容是否可复用，并可整理标题、问题、答案和标签；
- 发布器只能原子写入 `<document_root>/extra/*.md`；
- 一个扫描批次完成所有写入后，只触发一次结构化索引重载；
- 不保存完整聊天流水，不建立会话记忆，也不把原始缓冲暴露给检索工具。

## 3. 验收标准（EARS）

1. 当受控群组收到消息时，系统应将必要字段暂存于有界内存，并在 TTL 后清除。
2. 当进程重启时，系统不得从数据库或文件恢复原始群聊缓冲。
3. 当管理员引用一条仍在缓冲中的普通消息作答时，下一次扫描应形成一个强关联问答候选。
4. 当回复者不是已配置管理员、被引用消息不存在、内容为空或属于命令时，系统不得自动发布知识。
5. 当扫描周期触发而上一次扫描仍在运行时，系统应跳过本轮，不并发执行两个扫描批次。
6. 当反思器判定内容不可复用、包含敏感内容或置信度不足时，系统不得写入文档。
7. 当候选与已发布来源或规范化内容重复时，系统不得生成第二份文档。
8. 当候选通过自动发布策略时，系统应以 `.md` 原子写入 `extra`，且不得访问该目录之外的路径。
9. 当一个批次发布多个文档时，系统应在批次写入结束后只请求一次索引重载。
10. 当文档写入成功但索引重载失败时，系统应保留文档、保留旧索引并发送运维通知；后续扫描或手动重载应可恢复。
11. 当运行时配置改变扫描周期、群组范围或启用状态时，系统应热更新扫描策略，而不重启 Connector。
12. 当反思功能关闭时，系统不得缓存新消息、调用反思器、写入文档或触发索引重载。

## 4. 非目标

- 不保存或恢复聊天历史；
- 不从通讯平台主动拉取历史消息；
- 不根据纯时间邻近关系猜测问答配对；
- 不修改、覆盖或删除人工维护的文档；
- 不在首版加入向量检索、数据库或通用文件写入工具；
- 不允许文档内容或群消息获得系统指令、Shell、SecretStore 或管理 API 权限。

# v0.1.0 实施设计

日期：2026-11-03。依据：[requirements.md](requirements.md)。

状态：用户已于 2026-11-03 授权连续实施，进度与验证见 [tasks.md](tasks.md)。工程默认值可在实现和基准验证中调整；用户最新范围修正优先于旧阶段计划。

## 1. 分层与执行顺序

保留协议无关的 Engine、模块注册和 Connector Provider。增加的边界只服务已选定场景：操作结果、单存储后端、短期会话、共享决策、群事件与可选群操作。MCP/Skill 继续作为 Core 扩展，检索继续作为 Tool。

```text
连接器 → 规范消息/角色 → 核心准入与去重 → 运维命令分流
  → 明确 @ / 主动介入资格 → 图片支持检查
  → 短期会话顺序与快照 → 业务范围决策
  → 拒答/澄清，或按需工具 + 有界 Agent Loop
  → 发送前策略检查 → 投递 → 提交成功问答上下文

群事件 → 规范申请/成员事件 → 去重与功能授权
  → 入群审核策略 / 确定性欢迎模板 → 可选群操作 / 投递
```

@ 只绕过主动插话的等待/让位，不绕过业务范围、去重、授权或全局暂停。图片关闭提示属于已触发输入的确定性能力说明，不调用范围模型；未触发消息仍可保持沉默。

## 2. 操作结果：原因与执行确定性分离（R12）

新增小型操作结果/错误契约，建议放在 internal/operation，供已有领域包使用。保留 Go 的 error、errors.Is/As 和领域结果，不统一改成巨型 Result[any]。

- 稳定分类：invalid、not_configured、disabled、unsupported、unauthenticated、permission_denied、policy_denied、not_found、expired、conflict、rate_limited、budget_exhausted、busy、unavailable、timeout、canceled、internal、unknown。
- 成功空结果、duplicate、ignored、buffered、suppressed、already_processed 等是领域正常结果；不可误记为系统异常。
- 副作用确定性独立为 not_started、completed、partial、unknown。请求已发出但响应超时应表达 timeout + unknown，不自动重发。
- 跨边界保留 operation、资源标识和 cause；公开文案与诊断信息分离。HTTP/CLI/工具结果做映射，调用方不按错误字符串匹配分支。
- 不从所有供应商错误文本臆测权限或重试能力；明确可映射则转换，否则保留外部未知原因。

先改公共契约和已有边界映射，后续每项新能力沿用；不用一次机械重写所有内部辅助函数。

## 3. 单一文件后端与领域接口（R13）

进程启动时只选一个 persistence backend，首版只有 file。后端选择和数据位置属于静态配置，首期保留 runtime_config_path/secret_store_path，由同一 Backend 构建；不为统一抽象强制搬迁实际部署文件。后端提供配置版本、凭据与必要持久运营状态的领域仓储，消费者只接收自己需要的小接口。

```text
静态 YAML → Backend(file)
              ├─ 配置当前版本读写 / 历史查询
              ├─ Secret 状态与暂存/激活
              └─ 群申请等必要运营记录
```

- 复用 settings.Store 与 secret.Store 的有效语义，拆分消费者实际依赖，避免再建一套平行 ConfigStore。
- 持久对象有 schema_version、稳定 ID、revision、时间；条件更新和去重键在仓储语义中定义。业务不获取 SQL、NoSQL collection、物理文件路径或底层事务对象。
- 文件后端提供原子替换、恢复、有限历史与条件更新；需要原子修改的字段作为一个领域聚合提交。实际存在跨文件原子需求时用受控日志/恢复协议，不承诺不存在的跨后端事务。
- 配置候选、凭据激活和 Runtime 发布维持可恢复边界，失败不能落成“已保存但运行旧值且不自知”。后端契约测试验证版本冲突、写失败、恢复、凭据保护和读取隔离。
- 不热切换后端、不双写、不在故障时改用第二存储。进程内短期上下文、派生索引、日志和 Markdown 导出各有职责，不是持久仓储的隐藏副本。
- 本地文件格式可破坏式调整，但实际文件迁移前检查与备份；不得只因尚未发版就覆盖现有凭据或文档。

## 4. 模型必需与输入行为（R1–R3、R5）

- 运行模式校验有效回答模型与认证；init/doctor 走独立命令入口。LLM 服务可暂时不可达，但不能因缺少配置就回显伪装回答。
- llm.image_understanding 默认 false；init 明确生成值。已触发消息及其引用含图片时，false 分支仅回复“当前暂不支持图片”，不投递图片、不预检索、不做决策。
- 适配器先转换可靠描述/标准转义，未知表情使用中性占位或忽略，不把原始 CQ/平台控制段当系统指令。保留文字与引用，测试空 @ 与表情组合。
- 删除结构化检索模块的 /search 注册、直接调用 completer 路径和仅为其存在的依赖。保留 search_docs 和索引运维；通用 Command 注册是否保留按剩余消费者判断。

## 5. 有界 Loop 与短期上下文（R6–R7）

Engine 使用独立的有界回答执行器，每轮携带规范化 assistant/tool 消息。第一版工具串行执行，保留调用 ID；每次调用都走同一工具白名单、预算和 Hook。进度最多尝试一次，最终发送仍归宿主。

建议可配置默认值：run 总时限 90s、回答 LLM 最多 6 turns、工具总数 12、每轮工具数 4、单工具回传 16KiB、累计工具/中间上下文 128KiB。每步还受自身超时与父 context 约束；超限返回明确原因，不盲目重试。

短期会话服务由 Runtime 的进程级 owner 持有，Engine 仅持受限租约：

- 默认按 conversation_id + user_id 隔离，首期不默认共享群历史。
- TTL 20 分钟、最多 6 对成功问答、最多 1000 会话，且有全局字节上限；实际阈值在实现中集中配置与校验。
- 同一会话有界排队/顺序执行，跨会话并行；排队时间计入请求总时限，取消可退出。
- 发送成功才写入问答对；错误、模型决策、中间工具 payload 不写聊天记忆。投递结果未知不作为确认成功提交，也不自动重复回答。
- 主动介入的混合群批次不自动写入某个用户的私人问答记忆。
- 无关热更新保留当前会话服务；策略变更修剪数据并按请求快照生效，进程重启清空。旧 generation 关闭不能关闭新 generation 仍使用的服务。

## 6. 共享 Decision 服务与业务范围（R4、R9、R16）

internal/decision 管理任务目录、规范请求/结果、DM/LLM 路由、校验与预算；通过现有 capability 的受限接口交给内置消费者。它不是新的聊天协议或 FPP 接口。

- 任务按 ID/版本注册，先覆盖问题范围/依据需求、主动回复、管理员接答和群申请判断。每个任务有有界输入与有限枚举/真假/等级输出 Schema，显式 unknown/abstain。
- DM 供应商适配必须按实际官方协议确认；Jev 为候选，先做最小协议验证，不用虚构字段继续实现。未配置 DM 时用回答 Client 的独立决策提示词；不给它聊天 Skill、可执行工具或权限。
- 默认确定性规则优先；语义决策 DM 优先，无 DM 用 LLM。每次决策最多请求一个模型；DM 技术故障直接返回错误，不后备、不重试，unknown 不映射为 false。
- 建议单次 DM 时限 3s、LLM 决策时限 8s，均取父时限较小者；每聊天处理实例最多两次独立语义判断、入群审批最多一次；单次判断最多一个模型请求，同一输入/上下文快照可复用联合问题判断。后续基准再调默认值。
- 决策以本地严格 Schema 与领域校验为准；供应商原生结构化输出属于适配增强。Schema 合法不等于语义正确，LLM 自报置信度不与 DM 概率直接共用阈值。
- 业务范围由部署者显式配置；通用 Bot 默认不写死任何行业。启用范围限制后，域内、允许的日常交互、域外专业问题、未知分别处理；@ 和短期上下文都不能越过限制。
- 问题是否“容易”与是否属于范围分开。域外专业问题拒答，未知澄清；决策失败也不放行到无限制回答。
- 检索默认由回答模型选择。显式启用决策引导时，绑定工具 ID 与参数映射，通过同一工具执行器预先收集依据并计预算；不固定调用 search_docs、不写另一套检索循环、不静默替代缺失工具。
- 群审核可以消费决策，但动作有效性、权限和是否允许自动处理由宿主确认。无法判断时不操作申请，由管理员在原平台处理，欢迎模板无需调用模型。

## 7. 群级让位状态（R8）

让位状态由主动介入能力拥有，通过 Runtime 持有的受限状态服务跨 generation 保留；不复用全局 pause。

- 默认可信介入包括管理员明确引用待答问题、显式让位指令；其他语义接答可交 Decision。角色由连接器可信事件和配置管理员共同归一化，保留来源。
- 建议默认让位 5 分钟；新的可信接答刷新到期时间，到期恢复，也可授权手动恢复；普通闲聊不无限延期。
- 让位发生时丢弃待插话项；已经生成但尚未发送的主动回复在发送前检查群状态，不在恢复后补发。@ 请求独立处理，仍接受业务范围判断。
- 先保留明确 @ 的处理资格，同时可用该消息更新让位信号；不能先取消缓存就吞掉当前 @。

## 8. 群事件、群操作与欢迎（R10、R15）

扩充 platform/messaging 的规范事件边界，聊天消息、入群申请、成员入群分开建模；事件有稳定身份、逻辑群、发生时间和适配器提供的关联引用。绑定限制和认证适用于全部事件。

- 入群审核、公告发布、消息撤回分别为可选小接口，不扩张基础 Adapter 的强制方法集。宿主按逻辑群路由；支持/配置/权限可知性与执行结果分开。
- 首版公告只发布，入群自动审批默认关闭；审批通过不等于实际入群。撤回按群+消息引用操作，无法撤回返回实际分类。
- 入群审批采用正则与统一布尔模型判断，支持 AND/OR 短路；失败不操作，无持久审批记录或 Bot 人工审批入口。公告和撤回使用原有管理认证及持久化幂等记录。运维命令仅按需要补充，不默认开放 LLM 动作工具。
- 核实当前 OneBot 服务实现和 API 扩展，补真实适配；没有支持的特性保持 unsupported，不能声称跨 OneBot 实现通用。
- 新人欢迎由可关闭的内置欢迎功能消费 MemberJoined，按群模板发送；通过受限事件回复效果让宿主投递，不向任意模块交付全局发送权限。
- 普通成员真实入群触发，重放去重，默认不欢迎 Bot 自己或连接恢复的历史快照；不因群聊让位抑制欢迎事件，但服从全局暂停与投递规则。

## 9. 能力目录、CLI 与交付（R11、R14）

统一目录是只读投影视图，复用模块/连接器/工具/Skill/模型的实际状态，不创建第二个状态权威源。配置有效、已启用、已加载、健康和权限未知分开表示，公开字段脱敏。

- 管理 API 与 CLI capabilities 消费同一投影服务；doctor 默认静态/本地检查，网络或子进程探测用显式选项，不执行群管理副作用。
- init 生成最小 YAML、运行配置和凭据引用，显式声明图片能力，禁止无提示覆盖；未完成初始化可诊断但不能宣称 Bot ready。
- docs 是当前使用与架构说明，specs 是需求/设计/任务/验收；两者提交。运行数据、索引、媒体、日志、个人配置/知识库和本地 AI 工具设置忽略；生成器/测试中的公开夹具明确保留。
- 每个生产变更同步写中文边界注释和必要配置文档；最终提供 README_ZH.MD、README_EN.MD 与根入口。
- 用户已于 2026-11-03 确认 Apache-2.0；收尾加入官方 LICENSE 与实际依赖归属文本。第三方仍保留各自许可，不将项目许可视为覆盖第三方。

## 10. 工作与验收边界

实施使用新的专用分支，基于当前 master，保留现有未提交规格与个人 .claude 文件。准备文档先独立记录，生产代码按 tasks 的工作包分别验证、提交；不合并回 master、不打发布标签，直至相应交付获得授权。

每工作包有有意义的定向测试，公共契约变更再做全量 test/vet。真实 OneBot、真实 DM 和 race 作为独立验收证据记录；无外部服务时可用受控 HTTP/进程测试，但不得把模拟测试当作真实验收。失败回滚、预算耗尽、无 DM、域外拒答、不支持群操作是本版必测路径。

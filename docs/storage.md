# 存储与数据恢复

进程通过 `storage.backend` 单选持久化后端。当前仅支持 `file`，未填也使用 file；SQL/NoSQL 尚未实现，填写其他值会报错，不会自动降级。后端选择是静态配置，需要重启进程。

```yaml
storage:
  backend: file
runtime_config_path: runtime-local.json
secret_store_path: secrets.json
```

两个文件都是同一个文件后端的领域仓储，可以独立指定位置。生产组装入口只选择一次 Backend，再分别提供配置和凭据接口；未来数据库实现也必须提供相同领域语义，不把查询语言暴露给业务。未配置路径时对应管理能力不可用，不创建隐藏的第二个 Store。

运行时只持有凭据读取接口；管理端凭据接口只提供状态和写入生命周期，没有明文读取方法。`FORGEBOT_SECRET_KEY` 仍由进程入口解析，API Key 保持加密存放。

配置文档拥有 `schema_version`、稳定 `id=runtime/default` 和递增 `version`；条件更新必须匹配当前版本，回滚会产生新版本。旧格式读取时仅补齐元数据，首次更新才写新格式，原文件保留为 `.bak`。未来版本或错误文档身份会被拒绝，不会悄悄回退旧备份。

配置主文件损坏时可从 `.bak` 读取。恢复后的首次提交将损坏主文件另存为 `.recovery-invalid`，保留有效 `.bak`，避免替换过程中失去可用恢复来源。写入失败不会发布新的内存配置版本；恢复失败会保留错误链。

凭据格式 v2 保留候选版本分配序列，防止删除或丢弃后重用旧候选身份。v1 可读，首次修改前保留原始加密文件 `.format-v1.bak`；不同内容的旧迁移备份不会被覆盖。Windows 替换中断后若主文件缺失、只剩 `.replace-backup`，验证密文后恢复；损坏备份不会被当成空仓储。

每份部署数据应在停机后整体备份，凭据数据与加密主密钥分开妥善保管。当前不支持多个进程同时写同一数据目录，也不支持后端热切换、双写或跨后端事务。短期会话、派生索引、日志和 Markdown 导出不属于第二持久化后端。
